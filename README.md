**MyFilmLibrary** — локальное кроссплатформенное приложение для личной фильмотеки.
Фильмы, сериалы, аниме, сезоны, оценки, рецензии, цитаты и кадры хранятся в одном
месте — на вашем компьютере. Без регистрации, облака и обязательного подключения
к интернету.

Приложение работает на **Windows** и **Linux**, использует **Tauri 2**, **React 19**
и **SQLite**. База данных и изображения лежат в обычной папке, которую можно
скопировать, заархивировать или перенести на другой компьютер.

## Возможности

### Библиотека

- Фильмы, сериалы, мультфильмы, аниме, документальные фильмы и собственные категории.
- Подробная карточка: название, оригинальное название, режиссёр, год, жанры,
  страна, длительность, IMDb ID, теги, описание и личные впечатления.
- Статусы: «В планах», «Смотрю», «Просмотрено», «Брошено».
- Оценка от 1 до 10.
- Теги через запятую: «на пересмотр», «с друзьями», «любимое» и любые другие.
- Адаптивная сетка карточек с постерами, рейтингом, годом и статусом.
- Отдельная страница фильма со всей информацией, цитатами, кадрами и связями.

### Сериалы и сезоны

- Поддержка общего количества сезонов и отметок просмотренных сезонов.
- Сезоны можно добавлять отдельными карточками, привязанными к родительскому
  сериалу или аниме. Название, категория, режиссёр, жанры и постер
  предзаполняются автоматически.
- У каждого сезона может быть свой статус, оценка, описание и постер.
- На карточке сериала отображается «стопка» сезонов и их количество.
- В аналитике отдельно считаются просмотренные сезоны.
- Сезон можно отвязать от сериала и превратить в самостоятельную запись.

### Связи между фильмами

- Направленные связи: сиквел, приквел, ремейк, спин-офф и «связано».
- Со страницы продолжения связь подписана как «Сиквел», со страницы оригинала —
  как «Приквел».
- Связанный фильм открывается по клику.
- Связи сохраняются сразу, без ожидания кнопки «Сохранить».
- Повторные связи и связь фильма с самим собой отклоняются.
- При удалении фильма его связи удаляются каскадно.

### Обложки, кадры и цитаты

- Импорт обложки через системный диалог. Файл проверяется, копируется в папку
  приложения, а в базе сохраняется относительный путь.
- Вставка обложки из буфера обмена: кнопка «Вставить из буфера» или `Ctrl+V`.
- Для сетки автоматически создаётся миниатюра 300×450 px.
- Галерея кадров и скриншотов на странице фильма: добавление из файла,
  подпись и удаление.
- Любимые цитаты вводятся по одной на строку и красиво отображаются
  на странице фильма в виде блок-цитат.

### Поиск и фильтры

- Поиск по названию, оригинальному названию, режиссёру, жанрам, стране,
  году, тегам и IMDb ID.
- Поиск регистронезависимый и корректно работает с кириллицей.
- Фильтры по статусу и категории.
- Список категорий = встроенные категории + все категории из сохранённых записей.

### Аналитика

- Всего фильмов и просмотрено.
- Распределение по статусам: в планах, смотрю, просмотрено, брошено.
- Средняя оценка.
- Общее время просмотра в часах и минутах.
- Топ-5 жанров и топ-5 режиссёров.
- Общее количество сезонов и просмотренных сезонов.

### Резервные копии и экспорт

- **ZIP-архив** — полная резервная копия: фильмы, связи, кадры и постеры.
- **Импорт ZIP** — добавляет недостающие записи, пропускает дубликаты
  по IMDb ID или по названию и году, восстанавливает связи и кадры.
- **CSV** — выгрузка для Excel и Google Sheets с UTF-8 BOM.
- **Markdown** — каталог для Obsidian, Notion или GitHub.
- Архивы переносимы между Windows и Linux: разделители путей нормализуются.

### Интерфейс

- Тёмная и светлая темы с сохранением выбора в базе.
- Русский и английский языки, переключение в шапке.
- Навигация как в браузере: боковые кнопки мыши «назад/вперёд».
- Жест двумя пальцами по тачпаду: вправо — назад, влево — вперёд.
- Свайпы на сенсорном экране.
- Возврат к предыдущей странице с восстановлением позиции прокрутки.
- Понятные сообщения об ошибках и подтверждение удаления.

### Приватность

- Приложение не отправляет телеметрию и не требует аккаунта.
- В интернет оно выходит только по кнопке «Найти в OMDb» и только если
  пользователь добавил API-ключ.
- Ключ OMDb хранится локально в таблице `settings` файла `library.db`
  в открытом виде — не используйте общий ключ на чужом компьютере.

## Сборка

### Linux

Готовый скрипт:

```bash
chmod +x packaging/linux/build.sh
./packaging/linux/build.sh
```

Скрипт проверяет `npm` и `cargo`, собирает frontend и компилирует release-бинарник.
Результат:

```text
target/release/myfilmlibrary-app
```

Ручная сборка:

```bash
cd frontend
npm ci
npm run build
cd ..

cargo build --release --manifest-path src-tauri/Cargo.toml
```

Feature `custom-protocol` уже входит в `default`, поэтому frontend встраивается
в бинарник автоматически. Если понадобится собрать без неё, приложение будет
пытаться открыть dev-сервер и завершится с ошибкой подключения.

Сборка переносимой папки и архива:

```bash
mkdir -p dist/MyFilmLibrary-linux-x64
cp target/release/myfilmlibrary-app dist/MyFilmLibrary-linux-x64/
cp packaging/linux/run-portable.sh dist/MyFilmLibrary-linux-x64/
cp packaging/linux/com.myfilmlibrary.desktop dist/MyFilmLibrary-linux-x64/
tar -czf dist/MyFilmLibrary-linux-x64.tar.gz -C dist MyFilmLibrary-linux-x64
```

Запуск:

```bash
./dist/MyFilmLibrary-linux-x64/myfilmlibrary-app
```

### Windows

Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File packaging/windows/build.ps1
```

Скрипт собирает frontend, компилирует release-бинарник и складывает
переносимую папку в:

```text
dist/MyFilmLibrary-windows-x64/
```

Внутри:

- `myfilmlibrary-app.exe` — обычный запуск, данные в `%APPDATA%`;
- `run-portable.bat` — запуск с данными в папке `data` рядом с `.exe`.

При желании папку можно заархивировать:

```powershell
Compress-Archive -Path dist/MyFilmLibrary-windows-x64/* `
    -DestinationPath dist/MyFilmLibrary-windows-x64.zip -Force
```

## Портативный режим

В портативном режиме база, постеры и кадры лежат в папке `data` рядом
с исполняемым файлом. Приложение определяет каталог через переменную
окружения `MY_FILM_LIBRARY_DATA_DIR`.

**Linux:**

```bash
./run-portable.sh
```

**Windows:**

```bat
run-portable.bat
```

Вручную:

```bash
# Linux
MY_FILM_LIBRARY_DATA_DIR=/path/to/data ./myfilmlibrary-app
```

```powershell
# Windows PowerShell
$env:MY_FILM_LIBRARY_DATA_DIR = "D:\MyFilmLibrary\data"
.\myfilmlibrary-app.exe
```

Если переменная не задана, используется системный каталог приложения.

## Где хранятся данные

| ОС | Каталог |
| --- | --- |
| Windows | `%APPDATA%\com.myfilmlibrary.desktop\` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/com.myfilmlibrary.desktop/` |

Структура:

```text
com.myfilmlibrary.desktop/
├── library.db
├── posters/
│   ├── <имя>-<уникальный-id>.<ext>
│   └── thumb_<имя>-<уникальный-id>.<ext>
└── screenshots/
```

В базе хранятся относительные пути (`posters/...`, `screenshots/...`),
поэтому папку данных можно перенести на другой компьютер. Разделители
`\` и `/` нормализуются при чтении.

При первом запуске новой версии приложение автоматически переносит данные
из старого каталога `MyFilmLibrary`, если новый каталог ещё пуст:

- Windows: `%APPDATA%\MyFilmLibrary\` → `%APPDATA%\com.myfilmlibrary.desktop\`
- Linux: `~/.local/share/MyFilmLibrary/` → `~/.local/share/com.myfilmlibrary.desktop/`

Для резервной копии достаточно закрыть приложение и скопировать весь каталог
данных. Для переноса между машинами удобнее ZIP-архив из раздела
«Резервные копии».

## Архитектура

Поток данных однонаправленный:

```text
React UI
   │  invoke()
   ▼
Tauri commands (src-tauri)
   │
   ▼
myfilmlibrary-core
   ├── models    — доменные типы и валидация
   ├── db        — SQLite, CRUD, фильтры, статистика, миграции
   ├── storage   — постеры, кадры, пути, миниатюры
   ├── metadata  — OMDb
   └── transfer  — ZIP, CSV, Markdown
```

- `crates/core` не зависит от Tauri и UI.
- `src-tauri` — тонкий слой: принимает вызов из WebView и передаёт его в core.
- Frontend общается с Rust только через `invoke()`. Прямого доступа к SQLite нет.
- Тяжёлые операции выполняются в `spawn_blocking`, чтобы не блокировать UI.
- Обложка сначала проверяется как изображение, затем копируется в `posters/`.
  Если запись в базу не удалась, скопированный файл удаляется.
- При замене обложки старый файл удаляется только после успешного сохранения.
- При удалении фильма постер удаляется, если на него не ссылаются другие записи.

### Схема данных

<details>
<summary>Основные таблицы</summary>

| Таблица | Назначение |
| --- | --- |
| `films` | Фильмы, сериалы и сезоны. Поле `parent_id` связывает сезон с родительским тайтлом. |
| `film_relations` | Направленные связи: `source_id`, `target_id`, `kind`. |
| `film_screenshots` | Кадры и скриншоты: путь, подпись, позиция. |
| `settings` | Настройки приложения, в том числе ключ OMDb и тема. |
| `schema_migrations` | Применённые миграции. |

Ключевые поля `films`:

```text
id, title, original_title, category, director, year, genres, country,
runtime_minutes, imdb_id, tags, status, rating, description, thoughts,
poster_path, seasons_total, watched_seasons, quotes, parent_id,
sort_order, created_at, updated_at
```

Просмотренные сезоны хранятся строкой номеров (`"1,2,5"`) и нормализуются
при сохранении: без дублей и по возрастанию.

Цитаты хранятся JSON-массивом строк.

</details>

### Миграции

Миграции лежат в `crates/core/migrations/` и применяются по порядку
в транзакции. Применённые версии фиксируются в `schema_migrations`.

Чтобы добавить изменение схемы:

1. Создайте файл `crates/core/migrations/008_описание.sql`.
2. Добавьте пару в `MIGRATIONS` в `crates/core/src/db.rs`:

```rust
(8, include_str!("../migrations/008_описание.sql")),
```

Повторное открытие базы не применяет миграции заново.

## OMDb

Автозаполнение необязательно и работает только по нажатию кнопки
**«Найти в OMDb»** в редакторе.

1. Получите бесплатный ключ: [omdbapi.com/apikey.aspx](https://www.omdbapi.com/apikey.aspx).
2. Откройте «Настройки» и сохраните ключ.
3. В редакторе фильма нажмите «Найти в OMDb».

Что заполняется:

- оригинальное название;
- год;
- жанры (частые жанры переводятся на русский);
- режиссёр;
- страна;
- длительность;
- описание;
- IMDb ID;
- количество сезонов;
- постер, если своего ещё нет.

Заполняются **только пустые поля**. Введённые вручную данные не перезаписываются.
Без ключа приложение полностью работает офлайн, а кнопка предлагает открыть
настройки.

## Формат резервной копии

```text
myfilmlibrary-backup.zip
├── library.json
├── posters/
└── screenshots/
```

`library.json` содержит версию формата, фильмы, связи и список кадров.

При импорте:

- архив проверяется на поддерживаемую версию формата;
- недостающие фильмы добавляются;
- дубликаты пропускаются по IMDb ID или по названию и году;
- связи восстанавливаются с привязкой к существующим или новым записям;
- постеры и кадры распаковываются в локальные папки;
- в конце показывается сводка: добавлено, пропущено, восстановлено.

Архивы, созданные в Windows, корректно импортируются в Linux, и наоборот.
Старые архивы без полей `tags`, `quotes` и `parent_id` читаются с значениями
по умолчанию.

CSV и Markdown предназначены для чтения и обмена, а не для полного
восстановления библиотеки.

## Решение проблем

### `Could not connect to localhost: Connection refused`

Приложение запущено в dev-режиме и не нашло Vite-сервер.

- Для разработки используйте `cargo tauri dev`.
- Для release-сборки убедитесь, что включён feature `custom-protocol`
  (в этом проекте он входит в `default`).
- Vite слушает `127.0.0.1:5173`, и это же значение указано в
  `src-tauri/tauri.conf.json` → `build.devUrl`. Если порт занят, освободите его
  или синхронно измените оба значения.

### На Windows открывается пустое окно

Скорее всего, не установлен WebView2 Runtime. Установите его с сайта Microsoft
и запустите приложение снова.

### Мерцание или ошибки DMA-BUF на Linux / Wayland / NVIDIA

Попробуйте запустить с отключённым DMA-BUF:

```bash
WEBKIT_DISABLE_DMABUF_RENDERER=1 ./myfilmlibrary-app
```

В портативном скрипте это можно включить переменной:

```bash
DISABLE_DMABUF=1 ./run-portable.sh
```

### Не работает вставка из буфера обмена

- Убедитесь, что скопировано именно изображение, а не ссылка на страницу.
- На Wayland может понадобиться `xdg-desktop-portal`.
- Если кнопка не сработала, попробуйте `Ctrl+V` при открытом редакторе
  или на странице фильма.

### Не могу найти базу данных

- Обычный режим: см. таблицу «Где хранятся данные».
- Портативный режим: папка `data` рядом с исполняемым файлом.
- Если задана переменная `MY_FILM_LIBRARY_DATA_DIR`, приложение использует
  именно её.

### Приложение не запускается после обновления

Закройте старую версию, сделайте копию каталога данных и запустите новую.
Миграции применяются автоматически. Если база повреждена, восстановите её
из ZIP-архива или из резервной копии папки данных.
