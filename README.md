# Моя Фильмография

Локальное десктопное приложение для личной фильмотеки на **Rust + egui + SQLite**.
Работает без интернета: база и обложки лежат на диске пользователя.

## Возможности

- CRUD фильмов: название, оригинальное название, категория, режиссёр,
  год, жанры, страна, длительность, теги, статус, оценка 1–10, описание,
  личные мысли.
- Категории: «Фильмы», «Сериалы», «Мультфильмы», «Аниме», «Документальные»,
  «Другое» и любые свои.
- Теги: свои метки через запятую («на пересмотр», «с друзьями»). На карточке
  видны первые три, в редакторе — быстрые подсказки из уже существующих тегов.
- Статусы: «Хочу посмотреть», «Смотрю», «Просмотрено», «Брошено».
- Связи между фильмами: сиквел, приквел, ремейк, ответвление, «связано».
  Связь направленная, поэтому со страницы продолжения видно «Сиквел»,
  а со страницы оригинала — «Приквел». Связанный фильм открывается
  по клику.
- Сезоны сериалов: общее количество и отдельная отметка каждого сезона.
  На карточке видно `3/8 сезонов`, а в редакторе — «сериал не досмотрен»,
  пока отмечены не все сезоны.
- Импорт обложки через системный диалог: файл проверяется, копируется
  в локальную папку, в БД сохраняется путь к копии (оригинал можно удалить).
- Вставка обложки из буфера обмена (кнопка «Вставить из буфера» или Ctrl+V,
  когда фокус не в текстовом поле) — скачивать картинку файлом не обязательно.
  Если скопирован путь к файлу, он тоже принимается (включая `file://` URI
  файловых менеджеров Linux).
- Поиск по названию, оригинальному названию, режиссёру, жанрам, стране,
  году, тегам и IMDb ID (регистронезависимый, включая кириллицу), фильтры
  по статусу и категории.
- Клик по карточке открывает страницу фильма; карточки можно перетаскивать
  для изменения порядка, он сохраняется в БД.
- Навигация как в браузере: боковые кнопки мыши «назад/вперёд» и жест
  двумя пальцами по тачпаду (вправо — назад, влево — вперёд). Новая
  страница всегда открывается с начала, а возврат восстанавливает позицию.
- Экспорт и импорт фильмографии: ZIP-архив с `library.json` и копиями
  обложек. Импорт добавляет недостающие фильмы, пропускает дубликаты
  (по IMDb ID или названию и году) и восстанавливает связи.
- Необязательное автозаполнение из OMDb API: год, жанры, страна,
  длительность, режиссёр, описание, IMDb ID и обложка. Заполняются
  **только пустые поля** — введённые вручную данные не перезаписываются.
  Нужен бесплатный ключ, который хранится в локальной БД; без ключа
  приложение полностью автономно.
- Кадры и скриншоты фильма: возможность добавлять скриншоты через системный диалог или вставку из буфера обмена (Ctrl+V). Галерея кадров на странице фильма.
- Цитаты и любимые моменты: хранение цитат в БД и красивый вывод на странице фильма в виде блок-цитат.
- Страница профиля со статистикой (Dashboard): общее число фильмов, процент просмотренного, средняя оценка, общее время просмотра в часах, топ-5 жанров и режиссёров, диаграмма распределения по статусам.
- Светлая и тёмная тема: быстрое переключение темы оформления с сохранением выбора в SQLite (`settings`).
- Виртуализация сетки карточек (`ScrollArea::show_rows`): отрисовываются только видимые строки, что обеспечивает плавную прокрутку в библиотеках на 1000+ фильмов.
- Оптимизация размера обложек: при импорте постера генерируется уменьшенная копия (300×450 px), используемая в сетке для экономии видеопамяти и быстрой загрузки.
- Экспорт в CSV и Markdown: выгрузка каталога в CSV (с UTF-8 BOM для Microsoft Excel) и в форматированный Markdown-документ с цитатами и метаданными.
- Горячие клавиши: `Ctrl+N` — новый фильм, `Ctrl+F` — быстрый фокус на строке поиска, `Ctrl+S` — сохранение в редакторе, `Esc` — возврат / закрытие модальных окон.
- Полная обратная связь: всплывающие уведомления (toast) с возможностью закрытия для всех ключевых операций и ошибок.
- Удаление фильма — на странице фильма, с подтверждением. При удалении очищаются файлы обложек и прикреплённые кадры.
- Тёмная и светлая темы, адаптивная виртуализированная сетка.

## Стек

| Задача | Решение |
| --- | --- |
| GUI | `eframe` / `egui` 0.37 (рендерер `glow`) |
| БД | `rusqlite` 0.41 с feature `bundled` (SQLite внутри бинарника) |
| Ошибки | `thiserror` для доменных ошибок, `anyhow` в `main` |
| Файловые диалоги | `rfd` 0.17 |
| Изображения | `image` 0.25 (валидация, миниатюры 300×450) |
| Буфер обмена | `arboard` 3.7 (текст и изображения), feature `clipboard` у `eframe` |
| Каталоги | `dirs` 7 |
| Экспорт/импорт | `serde` + `serde_json`, `zip` 2.4 (deflate), `csv` 1.4 |
| OMDb API | `ureq` 3.5 с `rustls` (без системного OpenSSL) |

`egui` выбран вместо `iced`, потому что immediate-mode UI позволяет
быстро описать сетку карточек, форму и модальные окна без лишнего
управления состояниями и асинхронной архитектуры.

## Запуск

```bash
cargo run --release
```

### Windows

Нужен Rust stable и Build Tools для MSVC (для компиляции bundled SQLite).
Дополнительных библиотек SQLite не требуется.

### Linux

Для сборки `eframe` с `glow`/X11/Wayland обычно нужны:

```bash
sudo apt install build-essential pkg-config libxkbcommon-dev libwayland-dev \
    libx11-dev libxcursor-dev libxi-dev libxrandr-dev libgl1-mesa-dev \
    libegl1-mesa-dev
```

```bash
cargo build --release
./target/release/my-film-library
```

Поддерживаются и X11, и Wayland (в Wayland приложение использует
`app_id = "my-film-library"`). `rfd` использует XDG Desktop Portal, который
есть в обычных десктопных окружениях. В минимальных оконных менеджерах
может понадобиться `xdg-desktop-portal` и бэкенд под ваше окружение
(`xdg-desktop-portal-gtk`, `xdg-desktop-portal-kde` и т. п.), а также
`zenity` для диалогов-сообщений и запасного варианта выбора файла — иначе
системные диалоги могут не открыться.

Вставка изображения из буфера обмена под X11 работает всегда, а под
Wayland зависит от протокола `wlr-data-control` (обычно доступен в
wlroots-композиторах). Если композитор его не поддерживает, обложку можно
выбрать файлом или вставить путь к файлу текстом.

Переносимая сборка (база и обложки в `./data` рядом с бинарником):

```bash
mkdir -p ~/MyFilmLibrary-portable
cp target/release/my-film-library ~/MyFilmLibrary-portable/
cp packaging/linux/run-portable.sh ~/MyFilmLibrary-portable/
chmod +x ~/MyFilmLibrary-portable/run-portable.sh
cd ~/MyFilmLibrary-portable
./run-portable.sh
```

`run-portable.sh` выставляет `MY_FILM_LIBRARY_DATA_DIR` в `./data` и
передаёт все аргументы приложению.

## Где хранятся данные

Каталог определяется через `dirs::data_dir()`:

- Windows: `%APPDATA%\MyFilmLibrary\`
- Linux: `~/.local/share/MyFilmLibrary/`
- macOS: `~/Library/Application Support/MyFilmLibrary/`

Внутри:

```
MyFilmLibrary/
├── library.db
└── posters/
    └── <имя>-<уникальный-id>.<ext>
```

Если системный каталог недоступен, приложение использует `data/` рядом
с исполняемым файлом. В БД записывается **относительный** путь
(`posters/...`), поэтому папку данных можно перенести на другую машину.
Разделители путей (`\` и `/`) нормализуются при чтении, а старые
абсолютные пути Windows, открытые в Linux, сводятся к имени файла
в локальной папке `posters/`.

Библиотеку и ZIP-архив можно свободно переносить между Windows и Linux.

Для переносимого режима или тестов можно явно задать каталог:

```bash
MY_FILM_LIBRARY_DATA_DIR=/path/to/data cargo run --release
```

## Архитектура

Поток данных однонаправленный:

```
UI (egui) ──действия──> FilmApp ──CRUD──> Database (rusqlite)
                           │
                           ├── storage::{import_poster, delete_poster}
                           └── PosterCache (TextureHandle)
```

- `models` не зависит от GUI/БД.
- `db` не знает про UI; принимает `NewFilm`, возвращает `Film`.
- `ui/*` получает данные и возвращает одно действие (`LibraryAction`,
  `EditorAction`), а `FilmApp` уже решает, что делать с БД и файлами.
- Обложка сначала валидируется (`image::ImageReader`), затем копируется
  под новым именем. Если запись в БД не удалась — скопированный файл удаляется.
  При замене/удалении обложки старый файл удаляется только после успешного
  сохранения записи.
- Картинка из буфера обмена декодируется в память, проверяется по размерам
  и при сохранении записывается в `posters/` как PNG. Промежуточные файлы
  не создаются.

### Схема БД

```sql
CREATE TABLE films (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    title           TEXT    NOT NULL CHECK (length(trim(title)) > 0),
    original_title  TEXT    NOT NULL DEFAULT '',      -- миграция 003
    category        TEXT    NOT NULL DEFAULT 'Фильмы',-- миграция 002
    director        TEXT    NOT NULL DEFAULT '',      -- миграция 003
    year            INTEGER,                          -- миграция 004
    genres          TEXT    NOT NULL DEFAULT '',      -- миграция 004
    country         TEXT    NOT NULL DEFAULT '',      -- миграция 004
    runtime_minutes INTEGER,                          -- миграция 004
    imdb_id         TEXT    NOT NULL DEFAULT '',      -- миграция 004
    tags            TEXT    NOT NULL DEFAULT '',      -- миграция 005
    status          TEXT    NOT NULL CHECK (status IN
                        ('want_to_watch', 'watching', 'watched', 'dropped')),
    rating          INTEGER CHECK (rating IS NULL OR rating BETWEEN 1 AND 10),
    description     TEXT    NOT NULL DEFAULT '',
    thoughts        TEXT    NOT NULL DEFAULT '',
    poster_path     TEXT,
    seasons_total   INTEGER NOT NULL DEFAULT 0,       -- миграция 003
    watched_seasons TEXT    NOT NULL DEFAULT '',      -- миграция 003, "1,2,5"
    quotes          TEXT    NOT NULL DEFAULT '[]',    -- миграция 006, JSON-массив
    sort_order      INTEGER NOT NULL DEFAULT 0,       -- миграция 003
    created_at      TEXT    NOT NULL DEFAULT (strftime(...)),
    updated_at      TEXT    NOT NULL DEFAULT (strftime(...))
);

-- Кадры и скриншоты к фильму.
CREATE TABLE film_screenshots (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    film_id    INTEGER NOT NULL REFERENCES films(id) ON DELETE CASCADE,
    image_path TEXT    NOT NULL,
    caption    TEXT    NOT NULL DEFAULT '',
    position   INTEGER NOT NULL DEFAULT 0,
    created_at TEXT    NOT NULL DEFAULT (strftime(...))
);

CREATE INDEX idx_film_screenshots_film ON film_screenshots (film_id, position);

-- Направленная связь: source — это kind по отношению к target.
CREATE TABLE film_relations (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    source_id  INTEGER NOT NULL REFERENCES films(id) ON DELETE CASCADE,
    target_id  INTEGER NOT NULL REFERENCES films(id) ON DELETE CASCADE,
    kind       TEXT    NOT NULL CHECK (kind IN
                   ('sequel', 'prequel', 'remake', 'spin_off', 'related')),
    created_at TEXT    NOT NULL DEFAULT (strftime(...)),
    UNIQUE (source_id, target_id, kind),
    CHECK (source_id != target_id)
);

-- Настройки приложения (ключ OMDb).
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

Список категорий в интерфейсе = предопределённые значения +
`SELECT DISTINCT category FROM films`. Поэтому свои категории не требуют
отдельной таблицы: они сохраняются вместе с фильмами.

Просмотренные сезоны хранятся компактной строкой номеров (`"1,2,5"`).
При сохранении список нормализуется: без дублей и по возрастанию.
Порядок карточек хранится в `sort_order`; после перетаскивания позиции
перенумеровываются целиком.

Миграции применяются в транзакции и фиксируются в `schema_migrations`.
Чтобы добавить изменение схемы, создайте `migrations/006_*.sql` и добавьте
пару `(6, include_str!(...))` в `MIGRATIONS` в `src/db.rs`.

### Связи между фильмами

Связь всегда направленная: `source` — это `kind` по отношению к `target`.
Например, «Дюна: Часть вторая» — `sequel` для «Дюны». На странице каждого
фильма показываются обе стороны, но с разными подписями:

| kind | со стороны source | со стороны target |
| --- | --- | --- |
| `sequel` | Сиквел | Приквел |
| `prequel` | Приквел | Сиквел |
| `remake` | Ремейк | Оригинал |
| `spin_off` | Ответвление | Основной фильм |
| `related` | Связано | Связано |

Связи сохраняются сразу, не дожидаясь кнопки «Сохранить». Повторная связь
игнорируется, связь фильма с самим собой отклоняется. При удалении фильма
его связи удаляются каскадно (`ON DELETE CASCADE`).

### Экспорт и импорт

Кнопки «Экспорт» и «Импорт» на главном экране работают с ZIP-архивом:

```
filmography-backup.zip
├── library.json
└── posters/
    └── <имя-обложки>.png
```

- Экспорт сохраняет все фильмы в порядке отображения, все связи и копии
  обложек, которые реально существуют на диске.
- Импорт сначала читает `library.json` и проверяет версию формата, затем
  добавляет недостающие фильмы. Дубликатом считается тот же `imdb_id`
  либо одинаковые название и год; такие фильмы пропускаются, а связи
  прикрепляются к уже существующим записям.
- Обложки восстанавливаются в локальную папку `posters/`; файлы пересоздаются
  из архива, поэтому архив можно переносить между машинами и между ОС.
  Имена файлов извлекаются с учётом и `/`, и `\`, так что архив, созданный
  в Windows, корректно импортируется в Linux, и наоборот.
- Импортированные фильмы дописываются после существующих, порядок внутри
  архива сохраняется. По завершении показывается сводка: сколько добавлено,
  пропущено, восстановлено связей и обложек.

### Автозаполнение из OMDb

Кнопка «Заполнить из OMDb» в редакторе запрашивает метаданные по
оригинальному названию (или обычному, если оригинальное пустое) и году.
Запрос выполняется в фоновом потоке, UI не замерзает; результат приходит
через канал и применяется к открытой форме.

Что заполняется: оригинальное название, год, жанры (переводятся на русский),
режиссёр, страна, длительность, описание, IMDb ID, число сезонов и обложка.
Заполняются **только пустые поля**: уже введённые вручную значения
(в том числе русское название и описание) остаются как есть, а в тосте
показывается, сколько полей добавлено. Если заполнять нечего, приложение
так и сообщает и ничего не меняет. Обложка подставляется только если своей
ещё нет.

Нужен бесплатный ключ OMDb:
[omdbapi.com/apikey.aspx](https://www.omdbapi.com/apikey.aspx).
Ключ вводится в «Настройках» и хранится в `settings` таблице `library.db`.
Без ключа кнопка предлагает открыть настройки, а всё остальное работает
офлайн. Сетевые ошибки, неверный ключ и превышение лимита показываются
в тосте, приложение не падает.

### Поиск

Фильтры по статусу и категории выполняются в SQL, поиск по названию,
оригинальному названию, режиссёру, жанрам, стране, году и IMDb ID — в Rust
через `to_lowercase()`. Это осознанно: `LIKE ... COLLATE NOCASE` в SQLite
регистронезависим только для ASCII, а для кириллицы поиск должен работать
одинаково при любом регистре. Для локальной библиотеки объём данных
не является проблемой.

### Обработка ошибок

- `AppError` (`thiserror`) объединяет ошибки SQLite, I/O, `image`,
  валидации, путей, ZIP-архива и импорта.
- `MetadataError` отдельно описывает отсутствие ключа, «не найдено»,
  ошибки API и сети, чтобы показать понятное сообщение.
- Ошибки старта БД показываются отдельным экраном с кнопками
  «Повторить» и «Выйти».
- Ошибки операций показываются в нижней панели (toast), редактор сохраняет
  введённые данные и показывает ошибку рядом с формой.
- Частичные операции откатываются: неудачная запись в БД удаляет только что
  скопированную обложку; неудачный импорт не оставляет осиротевших файлов.

## Архитектурное проектирование синхронизации

Для синхронизации каталога между несколькими устройствами (ПК, ноутбук, Android-приложение) спроектированы 3 возможных варианта:

### Вариант 1: Файловая синхронизация через облачные диски или Syncthing (для v1.2)
- **Суть:** Перенос папки данных (`data/`) или автоматический экспорт/импорт ZIP-архива через облачные сервисы (Nextcloud, Syncthing, Dropbox, Google Drive).
- **Плюсы:** Не требует аренды сервера, сохраняется 100% автономность и приватность данных, работает офлайн.
- **Особенности:** Требует детекции конфликтов одновременной записи (Last-Write-Wins или сохранение файла с суффиксом `.conflict`).

### Вариант 2: P2P репликация SQLite через CRDT (например, `cr-sqlite`)
- **Суть:** Встраивание расширения на базе Conflict-free Replicated Data Types (CRDT). Каждая запись отслеживает версию изменения (vector clock или LWW). Устройства обмениваются изменениями по локальной сети или через Relay-сервер.
- **Плюсы:** Бесконфликтное слияние (merge) изменений, сделанных на разных устройствах одновременно.
- **Особенности:** Усложнение кроссплатформенной сборки SQLite расширений на Windows/Android/musl.

### Вариант 3: Клиент-серверная синхронизация (бэкенд на Rust / `axum`)
- **Суть:** Сервер на `axum`, авторизация по токену, API эндпоинты:
  - `POST /api/sync/push` — передача локальных изменений с момента последней синхронизации.
  - `GET /api/sync/pull?since={timestamp}` — получение изменений других устройств.
- **Плюсы:** Идеально подходит для мобильного клиента (Android / iOS), простое разрешение конфликтов, централизованный бэкап.

### Поля схемы БД для отслеживания изменений (подготовка к синхронизации):
1. `sync_id TEXT NOT NULL UNIQUE` (UUIDv4) — стабильный сквозной идентификатор записи, не зависящий от автоинкрементного `id` локальной базы конкретного устройства.
2. `updated_at TEXT NOT NULL` — метка времени последнего изменения в формате ISO 8601 (UTC).
3. `deleted_at TEXT` (Soft Delete) — при удалении фильма запись помечается датой удаления, чтобы факт удаления реплицировался на другие устройства, а не перезаписывался старыми копиями.
4. `version INTEGER NOT NULL DEFAULT 1` — монотонный счетчик версий для быстрого разрешения конфликтов по стратегии LWW (Last Write Wins).

## Возможные улучшения

- Асинхронный `rfd::AsyncFileDialog`, чтобы диалог не блокировал UI-поток.
- Управление категориями (переименование/удаление), сортировка, FTS5.
- Дополнительные источники метаданных (Kinopoisk/TMDB) через тот же фоновый механизм и выбор конкретного результата поиска.
- Полноценная реализация синхронизации (вариант 1 или 3).
